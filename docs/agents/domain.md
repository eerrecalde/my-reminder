# Domain Docs

## Before exploring

Read the root `GLOSSARY.md` and ADRs in `docs/adr/` relevant
to the area being explored.

If these files are absent, proceed silently. Domain modeling
creates them when terms or decisions are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: domain terms.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use the glossary’s terms in issues, proposals, hypotheses,
and test names. Reconsider unfamiliar terminology; record
real vocabulary gaps for domain modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing
ADR, referencing the decision and explaining why it merits review.
